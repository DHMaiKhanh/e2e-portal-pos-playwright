Nền hạ tầng

Xong

Phần này đã chạy, không phải đụng lại. Ghi ra đây để sau này dựng lại trên máy khác thì biết điểm xuất phát ở đâu.

  • Docker Desktop chạy, WSL2 được cấp ≥ 8GB RAM
  • docker compose -f ci/jenkins/docker-compose.yml up -d --build → 2 container sống
  • Wizard lần đầu đã qua, đã tạo user admin
  • 10 plugin cài sẵn từ ci/jenkins/plugins.txt — không phải bấm tay cái nào
  • Jenkinsfile đã nằm trên origin/main, local không lệch commit

Vì sao là Docker-in-Docker chứ không mount /var/run/docker.sock như hướng dẫn thường thấy trên mạng: Jenkinsfile dùng agent { docker { … } }, tức Jenkins sẽ bind-mount workspace vào container Playwright. Nếu daemon là daemon của host, nó resolve đường dẫn đó theo filesystem host → workspace rỗng, checkout biến mất, build đỏ khó hiểu.

BƯỚC 1

Khai báo tool Allure

Xong

Tại sao cần. Reporter allure-playwright chỉ ghi ra reports/allure-results/ — JSON và attachment thô, hàng chục nghìn file, mắt người không đọc được. Phải có binary allure generate mới dựng thành site HTML. Plugin allure-jenkins-plugin chỉ làm phần gọi binary rồi gắn link vào trang build; bản thân binary là app Java riêng, plugin không kèm theo.

Manage Jenkins→Tools→Allure Commandline installations
Bẫy

Đừng bấm nhầm Allure 3 (from PATH) installations ở ngay trên. Step allure(results: …) trong Jenkinsfile tìm tool loại AllureCommandlineInstallation; Allure 3 là loại khác, khai báo vào đó thì build vẫn không thấy tool.

Form mở ra thì điền:

TrườngGiá trịLý do
NameallureKhớp doc, và để sau này ghi rõ commandline: 'allure' thì không phải sửa lại
Install automatically✔ tíchJenkins tự tải binary về container ở build đầu rồi cache lại
InstallerFrom Maven CentralMặc định, không cần đổi
Version2.30.0Khớp "allure-commandline": "^2.30.0" trong package.json
Đã kiểm chứng

Đọc trực tiếp trong container thấy file org.allurereport.jenkins.tools.AllureCommandlineInstallation.xml đã có <name>allure</name> và installer 2.30.0, plugin allure-jenkins-plugin@2.35.2. Bước này hoàn tất.

Nếu dropdown Version rỗng

Nghĩa là Jenkins chưa tải xong metadata của tool installer. Ở bản 2.568 nút Check now không còn nằm ở Plugins → Advanced settings nữa mà chuyển sang tab Plugins → Updates, cuối danh sách. Bấm xong chờ khoảng 10 giây rồi mở lại trang Tools.

Không muốn dùng Allure? Xoá dòng allure(...) trong khối post của Jenkinsfile là bỏ được bước này — vẫn còn JUnit và Playwright HTML report. Nhưng Allure là thứ duy nhất giữ lịch sử xuyên qua các build: test nào flaky, test nào mới vỡ. Với suite E2E thì nên giữ.

BƯỚC 2

Chụp lại session đăng nhập

Đang tới

Tại sao có bước này. Portal đăng nhập bằng Google OAuth kèm xác thực 2 bước, không drive headless được. Nghĩa là suite không tự đăng nhập được trên Jenkins. Cách làm: chụp session một lần trên máy dev rồi nạp lên Jenkins dạng file bí mật.

Phải làm

File src/data/dynamic/auth/admin.json hiện có đã hết hạn — cookie sớm nhất trong đó hết hạn ngày 18/08, tức 7 ngày trước. Upload nguyên xi thì stage Preflight chặn build ngay.

PowerShell · thư mục gốc repo
# Mở browser thật — BẠN tự đăng nhập bằng tay
npm run auth

# Kiểm tra session mới có dùng được không
# (đây đúng là thứ stage Preflight chạy trên Jenkins)
npx playwright test --project=setup --reporter=list

Lệnh thứ hai pass thì mới đi tiếp. Fail ở local thì upload lên Jenkins cũng fail y hệt, chỉ tốn thêm một vòng build 40 phút.

BƯỚC 3

Tạo hai credential

Chưa làm

Hai file bị gitignore nên không đi theo repo: file môi trường và file session. Cả hai nạp vào Jenkins cùng một đường — kiểu Secret file.

Manage Jenkins→Credentials→System →Global credentials→Add Credentials
ID (gõ chính xác)KindFile upload
portal-pos-env-localSecret fileconfigs/env/.env.local
portal-pos-storage-state-localSecret filesrc/data/dynamic/auth/admin.json

Vì sao đuôi -local chứ không phải -stage

Jenkinsfile ghép chuỗi theo tham số build: portal-pos-env-${TARGET_ENV}. Máy này hiện chỉ có configs/env/.env.local, và file đó trỏ https://v2.dev-fastboypay.com — Portal dev thật, không phải localhost. Nên chạy TARGET_ENV=local là đủ, khỏi đi xin giá trị stage. Muốn thêm môi trường thì tạo thêm cặp portal-pos-env-stage + portal-pos-storage-state-stage.

Bẫy

Sai một ký tự trong ID là build đỏ ở stage Provision env. Tệ hơn: nếu thiếu file env, loadEnv rơi về mặc định → BASE_URL thành http://localhost:3000 → cả suite fail mà log không nói rõ lý do.

Vì sao đóng gói cả file thay vì tách từng biến thành credential riêng: sau này thêm biến mới chỉ cần sửa file trên Jenkins, không phải đụng vào Jenkinsfile.

BƯỚC 5

Build lần đầu

Chưa làm

Bấm Build Now. Lần này Jenkins chỉ đọc Jenkinsfile để nạp danh sách tham số rồi dừng — đây là hành vi bình thường của Jenkins với job có parameters, không phải lỗi. Từ lần thứ hai, menu bên trái đổi thành Build with Parameters.

Tham sốLần chạy thửGhi chú
TARGET_ENVlocalQuyết định cặp credential được nạp
TEST_PATHtests/e2e/customersThu hẹp phạm vi cho lần đầu; rỗng = chạy hết
GREPrỗngLọc theo tag, vd @smoke
WORKERS8Điểm bão hoà đã đo — cao hơn không nhanh hơn, nghẽn ở server Portal
TRACEoffretain-on-failure vẫn phải record mọi test, chậm thêm ~25%
RUN_QUALITY✔Lint + typecheck trước khi test

Một build chạy những gì

Installnpm ci, tải Chromium khớp version image
Qualitylint + typecheck
Provision envNạp hai secret vào workspace
PreflightPortal có tới được không, session còn sống không
E2E testsChạy suite; fail thì đánh dấu UNSTABLE chứ không dừng
postPublish report, archive, xoá sạch secret khỏi workspace

Vì sao triggers { cron(…) } bị comment sẵn: session Portal chết theo thời gian và phải chụp lại thủ công. Build đêm sẽ đỏ hàng loạt ngay khi session hết hạn — đó là tiếng ồn chứ không phải tín hiệu. Bật lại khi nào có cách làm mới session tự động.

BƯỚC 6

Đọc kết quả

Chưa làm

Vào trang build vừa chạy, sidebar bên trái có bốn thứ:

  • Test Result (JUnit) — số pass/fail và xu hướng qua các build
  • Playwright HTML Report — report quen thuộc, xem được từng bước test
  • Allure Report — thống kê chi tiết hơn, giữ lịch sử xuyên build
  • Build Artifacts — results.json, screenshot / video / trace của test fail

Ba màu build

SUCCESSToàn bộ test pass.
UNSTABLECó test fail — lỗi nằm ở app hoặc ở test. Mở report ra xem.
FAILUREHỏng trước khi test chạy: install, lint/typecheck, hoặc Preflight đỏ.

Tách vàng khỏi đỏ là có chủ ý: "test tìm ra vấn đề" và "pipeline không chạy nổi" là hai chuyện khác nhau, cần người khác nhau xử lý.

Tra cứu nhanh

Lệnh dùng hằng ngày

PowerShell · thư mục gốc repo
# Xem log Jenkins theo thời gian thực (Ctrl+C để thoát)
docker compose -f ci/jenkins/docker-compose.yml logs -f jenkins

# Restart sau khi sửa cấu hình
docker compose -f ci/jenkins/docker-compose.yml restart jenkins

# Dừng Jenkins, GIỮ NGUYÊN job + credentials + lịch sử build
docker compose -f ci/jenkins/docker-compose.yml down

# Bật lại
docker compose -f ci/jenkins/docker-compose.yml up -d

# Build lại image sau khi sửa Dockerfile / plugins.txt
docker compose -f ci/jenkins/docker-compose.yml up -d --build

# XOÁ SẠCH: mất hết job, credentials, lịch sử. Chỉ khi muốn làm lại từ đầu
docker compose -f ci/jenkins/docker-compose.yml down -v

Khác biệt duy nhất cần nhớ: down giữ dữ liệu, down -v xoá luôn volume jenkins-data. Gõ nhầm -v là phải làm lại toàn bộ runbook này.

Khi nâng version Playwright

Tag image trong Jenkinsfile phải khớp @playwright/test trong package-lock.json. Hiện tại là mcr.microsoft.com/playwright:v1.61.1-noble. Lệch version thì browser bundled trong image không dùng được — stage Install vẫn tự tải bản đúng nhưng chậm hơn nhiều.
